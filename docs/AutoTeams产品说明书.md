## 0. 30 秒看懂 AutoTeams

AutoTeams 是**企业 AI 进化引擎**。它既不做一个"会聊天的 AI 助手"，也不做一个"编排 Agent 的搭建器"，而是把一家企业现有的**数字资产**（文档、SOP、流程、CRM、订单、知识），像"编译程序"一样，**编译成一支能顶岗干活的 AI 数字员工团队**，并让这支团队一边干活、一边持续自我进化。

| 维度 | 传统 AI 助手平台 | Agent 搭建器 | **AutoTeams（企业 AI 进化引擎）** |
|------|----------------|-------------|--------------------------------|
| 输入 | 一个文件夹的文档 | 开发者的几段代码 | **企业全量数字资产**（文件 / 结构 / 流程 / 知识） |
| 输出 | 一个可问答的助手 | 一个可调用的 Agent | **一整套能顶岗干活的 AI 数字员工团队** |
| 交付价值 | 知识问答 | 单点能力 | **直接交付业务结果**（报价单、订单、工单、客户反馈） |
| 生命周期 | 一次性生成 + 手动维护 | 开发者持续维护 | **持续自我进化**（自动识别缺口、建议优化、一键应用） |
| 对企业的意义 | 一个工具 | 一个框架 | **一套劳动力系统** |

> **最想让你记住的一句话**：AutoTeams 不是"给企业装一个 AI 助手"，而是"把企业现有的资料，编译成一支顶岗干活的 AI 员工团队"。

核心转化链路：

```
企业数字资产 → 企业运行模型 → Enterprise Runtime → AI 数字员工
    → AI 原生组织 → 业务执行 → 业务结果 → 持续进化
```

## 1. 它是什么：把企业"编译"成 AI 数字员工团队

AutoTeams 最独特的地方，在于它把企业**当作一个系统来"编译"**，而不是把文件当作"问答素材"。

企业只需要"指一套数据、回答几个业务问题"，系统就会在后台自动完成——**理解企业 → 编译组织 → 生成 AI 员工 → 投入业务协作**。它由三层环环相扣的能力构成：

| 层 | 作用 | 类比 |
|----|------|------|
| **企业编译器**（Enterprise Compiler） | 把企业理解透，编译出可运行的 Enterprise Runtime | "搭舞台" |
| **AI 数字员工**（AI Workforce） | 在 Runtime 上各司其职、协作产出业务结果 | "安排演员" |
| **进化引擎**（Evolution Engine） | 持续观察、分析、优化，让整个组织越用越聪明 | "教练与导演" |

**设计原点：今天能用，明天见结果。** 系统不承诺一次部署就 100% 完美，而是渐进式地理解企业、如实给出"完成度"，并引导用户补足数据，让 AI 从高级工具逐步变成企业日常运营的一部分。

## 2. 为什么做：横在企业与 AI 之间的四道墙

过去几年，几乎每家中小企业都听过"要让 AI 落地"，但真正落地的屈指可数。原因不是 AI 不够强，而是**横在企业与 AI 之间的四道墙**。

### 墙一：AI 落地门槛太高
- **痛点**：大多数企业没有 AI 工程师，不懂 Prompt、embedding、RAG、模型调优。
- **AutoTeams 的解法**：**零门槛的一键式部署**。用一个内置的**交互式企业访谈**像企业顾问一样追问关键问题（销售、客服、采购、财务、人事、权限、KPI），把"最懂业务的人"直接变成"AI 的配置者"；前端还支持**语音输入**，降低输入摩擦。

### 墙二：AI 只"会聊"不"会干活"
- **痛点**：市面上很多 AI 产品只能回答问题，无法真正参与业务流程、交付业务结果。
- **AutoTeams 的解法**：输出的**不是聊天机器人，而是能落地业务的数字员工**。每个 AI 员工绑定真实的岗位、SOP、权限和 KPI，能加入"询盘 → 报价 → 审批 → 成交 → 售后"这样的事件驱动协作，最终交付业务结果。

### 墙三：部署一次就算完，不会随业务进化
- **痛点**：传统 AI 部署是一次性的，业务一变，效果就退化，没人维护。
- **AutoTeams 的解法**：内置**进化引擎**。系统持续观察运行状态、识别知识缺口、发现流程瓶颈，以"AI 优化顾问"的形式给出建议，并在用户确认后一键应用，让整个组织持续变聪明。

### 墙四：数据安全与信任顾虑
- **痛点**：企业最怕把核心数据交给第三方，也最怕 AI"不受控"地乱做事。
- **AutoTeams 的解法**：**控制权始终握在企业手中**——数据只连接不搬运、全程加密与审计、权限继承企业组织架构、每个 AI 员工的权限都可见可控；涉密文件物理隔离进沙箱。并通过**影子模式**让 AI 先与真人并行、证明可靠后再接管，让"信任"看得见。

## 4. 六大产品模块：真的在界面上能看到、能操作

AutoTeams 前端将全部功能整合为 **6 组导航（驾驶舱 / 构建工坊 / AI 团队 / 知识中枢 / 进化中心 / 系统）**，全部为中文界面。以下每个模块描述的都是**当前已实现、可在界面上真实操作**的内容。

### 4.1 驾驶舱 · 今日 AI 公司
- 顶部统计卡：今日任务数、完成率、在岗 AI 员工、平均满意度；
- 待审批事项与告警：老板需要审批什么，一目了然；
- 运营概览指标 + 生命周期条；通过 SSE 推流 + 轮询降级实现"实时运转"，并诚实标注 LIVE / POLL 模式。

### 4.2 构建工坊 · 企业构建
- **五级编译**：信息 → 知识 → 流程 → 能力 → 运行时，逐级可视化（每级有输入、处理、产出），非黑箱；
- **Enterprise Runtime**：运行态组织实例，支持版本管理、版本间 diff 对比、回滚到任意历史版本（回滚前自动为 AI 员工创建配置快照）；
- **完成度评估**：如实给出完成度百分比与各维度评估，并建议补充哪些数据可提升多少。

### 4.3 AI 团队 · AI 员工 + 协作工作台
- **AI 员工**：系统基于岗位能力矩阵自动推荐（岗位抽取→优先级排序→配置生成→用户确认→正式创建），每个员工配置岗位、技能、知识库、工具、权限、system_prompt；生命周期管理（当前实现 招聘→培训→正式上岗 3 阶段，每次转换记录原因供审计）；
- **员工档案卡**：像管理一支真实团队——基本信息、岗位职责、当前任务、协作对象、最近完成的工作、运行表现指标、知识与工具、权限、成长记录；
- **协作工作台**：一个独立的实时协作环境（Express + WebSocket 服务），AI 员工与用户流式对话，支持工具调用、Skills、执行轨迹可视化，并加载该员工绑定的企业知识。

### 4.4 知识中枢 · 知识与技能
- **知识库**：上传/管理知识文档，向量化入库（ChromaDB），支持增量更新与文件自动监控；
- **技能（Skill）**：AI 自动生成技能 → 静态安全筛查 → 低风险自动审批 → 链式执行（文本生成、摘要、分类、数据抽取、翻译、代码生成、自定义、搜索、查询等 10 种处理能力）；
- **智能体编排画布**：以 LangGraph 状态机可视化构建过程（规划→扫描→[人工审批]→解析→向量化→构建→测试），构建到审批节点时暂停、可人工介入、状态可恢复。

### 4.5 进化中心 · 组织进化 + 影子模式 + 审计
- **组织进化**：AI 优化顾问（知识补充 / 流程优化 / 能力增强 / 组织调整 4 类建议，"用户确认后一键应用"）；AI 组织分析（Agent 工作量 / 流程效率 / 工具使用 / 业务贡献 / AI 成熟度 L1-L5 5 类指标）；进化时间线聚合建议、优化、版本变化事件；
- **影子模式**：状态机（影子并行 → 对比评估 → 达标 → 自主接管），创建影子任务、记录真人基线答案与 AI 生成答案、评估置信度、晋升（接管）或降级（继续观察）；前端以三阶段渐进信任建立（影子/监督/授权）呈现；
- **审计日志**：管理员可查看全量操作审计（HMAC 链防篡改）、按时间/操作者/动作检索。

### 4.6 系统 · 设置
- 企业信息、成员管理、会话与偏好设置等。

## 5. 六大核心亮点

### 亮点一：不是"问答助手"，而是"企业编译器"
AutoTeams 不把文件当"问答素材"，而是把企业**当作一个系统来编译**——产出统一的、可被 AI 员工直接读取运行的 **Enterprise Runtime**。AI 员工读取的是同一份 Runtime，而不是一堆零散的数字文件。这是它与所有"AI 助手""RAG 问答"产品的**本质区别**。

### 亮点二：不是"聊天机器人"，而是"顶岗干活的 AI 数字员工"
AutoTeams 输出的 AI 员工绑定真实岗位、SOP、权限和 KPI，能加入"询盘 → 报价 → 审批 → 成交 → 售后"的事件驱动协作，**直接交付业务结果**（报价单、订单、客户反馈、处理完成的工单）。协作全程支持人机协作的三种模式之一——"AI 提议人类确认"与"人类审批介入"均已实现。

### 亮点三：影子模式，把"信任"变成可量化、可交付的东西
AI 员工上线前先进入**影子模式**，与真人并行处理相同任务，结果对比一致且更优时才逐步接管。这把"企业对 AI 的信任建立过程"本身，变成了一个可量化、可可视化的交付物——这是企业级 AI 产品中非常少见、也非常关键的设计。

### 亮点四：进化引擎，让组织越用越聪明
部署只是第一步，**持续进化**才是 AutoTeams 真正想交付的能力：AI 优化顾问给出建议、Loop 闭环自动识别知识缺口并优化检索、检测到 RAG 质量连续退化时**自动回滚**到上一稳定版本、进化时间线可视化组织演进历程。企业不是"部署完就结束"，而是拥有一个**持续自我进化的 AI 原生组织**。

### 亮点五：Agentic RAG，可验证、可自我评估的 AI 链路
AutoTeams 的 RAG 不是简单的"检索→生成"，而是具备自我评估与自适应：查询分类路由（LLM 优先 + 规则兜底）、ReAct 多轮检索、Self-RAG 自验证（抑制幻觉）、三级重排序（BGE 重排序 → LLM 重排序 → 启发式降级）、结构感知分块、中文优化（默认 `BAAI/bge-large-zh-v1.5`）。每次回答都有**来源引用**，可溯源。

### 亮点六：生产级工程与安全，不是"能跑就行的 Demo"
24 个后端路由、1300+ pytest 测试用例、Alembic 迁移、C1-C7 安全加固（JWT+Refresh+重放检测、CSRF、CORS、RBAC、企业隔离、涉密沙箱、上传三重校验、Prompt 注入防护、审计日志 HMAC 链）、CI 安全门禁（ruff/pip-audit/npm audit/Trivy/SBOM）、Docker Compose + Vercel + Railway 部署上线。**技术实现的完整度与严谨性，经得起评审核验。**

## 6. 技术实现与创新：AI 链路可验证，不是 PPT

> 复赛评审标准强调"技术实现、AI 链路可验证"。本节所有实现均可定位到仓库中的具体文件、接口与测试。

### 6.1 五级编译流水线
```
Information → Knowledge → Process → Capability → Runtime
信息          知识          流程          能力          运行时
```
每级编译器有明确的输入、核心逻辑、产出与置信度评估。完整实现于 `backend/app/services/compiler/`，支持全量/增量编译、完成度计算、进度可视化、源码可读。

### 6.2 Enterprise Runtime 版本管理
运行态组织实例持久化，支持版本列表、版本间 diff、回滚到任意历史版本（回滚前自动为 AI 员工创建配置快照）——为"进化"提供可回退的安全底座。

### 6.3 LangGraph 状态机 + 人工审批（HITL）
Agent 构建不是黑盒，而是可中断、可审批、可恢复的状态机：`planner → scanner → [HITL 人工审批] → parser → vectorizer → builder → tester`。构建到审批节点时暂停，启发式自动审批（文件数 ≤ 50、总大小 ≤ 100MB、无敏感扩展名），状态持久化，前端以流水线步骤条可视化。

### 6.4 Agentic RAG 双通道
查询分类路由 + ReAct 多轮检索 + Self-RAG 自验证 + 三级重排序 + 结构感知分块 + Loop 闭环（分析反馈 → 识别缺口 → 优化检索 → 一键应用 → 质量退化自动回滚）。

### 6.5 三级记忆
短期记忆（对话上下文，内存/Redis）+ 长期记忆（历史摘要，ChromaDB）+ 实体记忆（客户偏好、商机上下文，关联知识图谱实体），实现跨任务、跨时间的业务连续性。

### 6.6 事件驱动协作 + 回滚
EventBus 事件总线 + 审批门（ApprovalGate）+ 操作前置快照的回滚机制（RollbackManager）；内置 7 步业务演示（new_inquiry → product_query → quotation → financial_review → approval → deal_closed → customer_sync / after_sales）。

### 6.7 多模态与多模型
音频转录（faster-whisper，支持中文）、图片多模态分析、视频（ffmpeg 提取关键帧 → LLM 分析 + 转录 + 摘要）；LiteLLM 适配多厂商（DeepSeek/豆包/通义/智谱/OpenAI 等），强/弱模型分级、故障转移。

### 6.8 安全体系（C1-C7 全量实施）
JWT + Refresh 轮换 + 重放检测、CSRF Double Submit、CORS 白名单、RBAC + 企业隔离校验、涉密文件物理沙箱、上传三重校验（扩展名/MIME/Magic Bytes）、Prompt 注入防护、审计日志 HMAC 链、Prometheus + Sentry + request_id 全链路追踪。
