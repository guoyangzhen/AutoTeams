# AutoTeams Local Runner

在工作台注册本地目录后，运行生成的 `autoteams-runner connect` 命令。只读目录只提供文件读取与列表；读写目录另外支持受限的写入和删除。此连接不提供通用命令执行。

## 连接与重试

- 连接命令中的令牌只能认领一次。成功认领后断线，Runner 退出并提示在工作台重新授权目录，使用新生成的命令；旧命令无法用于自动恢复。
- 认领前的网络故障可按指数退避重试，最多五次。建立 WebSocket 本身不重置退避计数；连接握手和认领等待都有超时。
- 服务端明确拒绝授权（WebSocket 1008）或 HTTP 400/401/403/404/410/426 时直接退出。需检查地址、服务和目录授权，不循环尝试无效凭据。
- 认领前不接受文件任务。本地目录校验失败同样退出，修正目录并重新授权后再连接。
- 连接诊断不输出令牌、URL 用户信息、非授权ID查询参数、服务端关闭原因或原始错误正文；失败通过状态码和操作提示诊断。
- 退出时停止连接与重试定时器，并等待物理浏览器会话清理，最多三秒。清理超时或失败会提示检查本机进程，不宣称保证回收所有外部进程。

这些规则只适用于目录桥接的一次性认领协议，并不新增持久重连凭据、自动重新授权或设备级跨实例恢复。手动退出为退出码0，配置/授权错误和重试耗尽为退出码1。

## 可选的物理设备执行

管理员须先在云端单独注册物理设备，取得设备 ID、注册时指定的 Runner ID 和该设备的长期凭据。目录授权不会注册设备。为同一个 `connect` 命令配置以下环境变量后，Runner 会使用设备身份换取短期令牌并启动物理心跳：

```powershell
$env:AUTOTEAMS_API_URL = 'https://api.example.com'
$env:AUTOTEAMS_DEVICE_ID = '<已注册设备 ID>'
$env:AUTOTEAMS_RUNNER_ID = '<注册时的 Runner ID>'
# 由本机密钥管理器注入 AUTOTEAMS_DEVICE_SECRET，不要写入脚本或连接命令。
autoteams-runner connect --server <bridge地址> --token <一次性令牌> --grant <授权ID> --path <本地目录>
```

也可通过 `--api`、`--device-id`、`--runner-id` 提供非秘密配置。CLI 支持 `--device-secret`，但环境变量可避免长期凭据出现在进程参数中。缺少任一物理身份字段会在连接前报错；旧的 `--bridge-secret` 和 `AUTOTEAMS_BRIDGE_SECRET` 已停用。

物理动作的回执默认按设备 ID 与固定 Runner ID 保存在用户目录 `.autoteams/runner-data/receipts/`。已有 `.autofde/runner-data/receipts/` 账本或锁的设备继续使用旧路径及原锁；若新旧路径同时有对应账本或锁，物理执行会暂停，等待人工核对。也可用 `AUTOTEAMS_RECEIPT_LEDGER` 指定路径。此目录应随设备资料一起备份。同一账本只允许一个物理 Runner 进程使用；异常退出留下 `.lock` 文件时，先确认旧进程已退出、核对回执，再人工处理锁文件。账本无法读取或记录达到 500 条时，Runner 暂停新的物理动作并保留原文件；需先核对并归档历史回执，再恢复运行，不能直接清空账本重试未确认的动作。物理账本故障不会阻止独立的目录文件连接。

## 本地验证

`npm test` 包含真实 CLI 子进程和本机 WebSocket/HTTP 服务验证：参数传递、敏感日志、认领前有限重试、认领后退出、授权拒绝及未认领任务拒绝。测试只授权仓库内随机生成的测试目录，不启动常驻演示或访问外部模型。

运行 `npm run typecheck` 检查类型；`npm run build` 更新实际 CLI 使用的 dist 产物。
