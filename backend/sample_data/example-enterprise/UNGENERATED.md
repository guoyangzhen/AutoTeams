## 2. 指南中存在歧义或未明确说明的处理

### 2.1 客户 ID 格式

- **歧义点**：生成指南 §4.6 字段说明中示例为 `C001`（无连字符），但 §6.1 ID 命名规范中规定为 `C-NNN`（有连字符，示例 `C-001`）。
- **处理**：采用 §6.1 的 ID 命名规范（`C-001` 格式），因为 §6.1 是专门的 ID 规范章节，更具约束力，且与员工 ID（`SL-YYYY-NNN`）、商机 ID（`OPP-NNN`）等连字符风格一致。
- **影响**：所有客户相关 CSV（customers / contacts / opportunities / activities / orders）均统一使用 `C-001` 格式，跨文件引用一致。

### 2.2 产品型号与订单 product_id

- **歧义点**：生成指南 §4.7 订单字段 `product_id` 示例为 `SL-T100`（基础产品编号），但价格表（§4.5）按型号细分（如 `SL-T100-RTU`、`SL-T100-MQTT` 等不同通信协议版本价格不同）。
- **处理**：订单 `product_id` 使用具体型号编号（如 `SL-T100-RTU`），与价格表型号一一对应，确保单价可从价格表查询，业务逻辑自洽。
- **影响**：校验脚本第 4 项确认 20 条订单的 11 个 product_id 全部存在于价格表中。

### 2.3 商机 stage 字段值

- **歧义点**：生成指南 §4.6 商机字段 `stage` 列举值为"线索/跟进中/报价中/审批中/已成交/已丢单"，但未明确"审批中"是否为独立阶段（v1 审批流程无金额分级，v2 才有）。
- **处理**：保留全部 6 个阶段值，其中"报价中"2 条用于演示报价场景触发，"审批中"1 条用于演示审批流程。两个阶段并存不影响 v1/v2 对比演示。
- **影响**：校验脚本第 3 项确认至少 1 条"报价中"商机。
